# 08. 설치코너 관리 화면 만들기 — 공지사항 견본 복사 따라하기

> 2026-11-15 작성. 대상: 프론트 담당(김태균 선임)과 각자의 Claude.
> 방식: **공지사항 견본(팝업형 CRUD)** 파일을 복사 → "견본 몇~몇 줄을 어떻게 바꾸나" 를 파일마다 적었다.
> 줄 번호는 2026-11-15 `main` 기준 견본 파일의 줄이다. 견본이 바뀌면 줄이 밀릴 수 있다 → 줄 옆에 적은 **코드 첫머리**로 찾는다.

## 0. 먼저 알아 둘 것 (짧게)

- **비유**: 공지사항 견본 = 붕어빵 틀. 틀을 통째로 복사하고, 이름(공지 → 설치코너)과 속(컬럼)만 바꾼다.
- **테이블**: 코너 정본 = `TB_SCRT_INST_PST` (설치위치/업체관리ID매칭코드, 컬럼 57개)
  - PK = `OFC_CODE CHAR(6)` + `INST_PST_CODE VARCHAR2(3)` → **키가 2개**다. 공지(번호 1개)와 다른 점은 이것 하나가 거의 전부.
  - 키가 2개인 부분은 **기기정보 견본**(`web/mcninfo/**`, 키 = 사무소+기번)에서 몇 줄 가져온다.
  - 출처: `db/ddl/_source_columns.csv` 154~210행, 참고 DDL `db/ddl/TB_SCRT_INST_PST.sql`.
- **이 가이드에서 화면에 쓰는 컬럼(잠정 — 현업·Figma 확인 필요, §9 질문 Q-18)**

  | 컬럼 | 뜻 | 타입 | 화면 |
  |---|---|---|---|
  | `OFC_CODE` | 사무소코드 | CHAR(6) PK | 조회조건·등록(수정 때 잠금) |
  | `INST_PST_CODE` | 코너코드 | VARCHAR2(3) PK | 등록(수정 때 잠금) |
  | `INST_PST_NM` | 설치장소명(코너명) | VARCHAR2(80) NOT NULL | 조회조건(부분일치)·등록·수정 |
  | `VEND_CODE` | 업체코드 | VARCHAR2(2) NOT NULL | 등록·수정 (어느 업체 코드인지 Q-01) |
  | `OP_BGN_TIME` / `OP_END_TIME` | 영업시작/종료시간 HHMM | VARCHAR2(4) | 등록·수정 |
  | `USE_YN` | 사용유무 | CHAR(1) NOT NULL | 조회조건·등록·수정, **삭제 = `USE_YN='N'`** |
  | 감사 4컬럼 | `CRT_DTM`… | — | 자동(`AuditInterceptor`) |

- **삭제 방식**: 공지는 물리 삭제지만, 코너는 기기(`TB_MCN_INFO.INST_PST_CODE`)가 가리키므로 **기기정보처럼 논리 삭제**(`USE_YN='N'`, 1건씩)로 한다(잠정 Q-18).
- **이름 정하기(한 번 정하면 모든 파일에 똑같이)**

  | 쓰는 곳 | 공지 견본 | 설치코너 |
  |---|---|---|
  | 화면키 | `sample.notice` | `mgmt.instCorner` |
  | 라우트·메뉴 경로 | `/sample/notice` | `/mgmt/inst-corner` (자동 계산) |
  | 팝업 화면키 | `popup.noticeEdit` | `popup.instCornerEdit` |
  | 프론트 파일 이름 | `notice.ts`, `Notice*.tsx` | `instCorner.ts`, `InstCorner*.tsx` |
  | 타입·API 객체 | `Notice`, `noticeApi`, `noticeKeys` | `InstCorner`, `instCornerApi`, `instCornerKeys` |
  | API 경로 | `/api/notice` | `/api/inst-corner` |
  | 백엔드 패키지 | `kr.co.nh.atms.web.notice` | `kr.co.nh.atms.web.instcorner` |
  | 응답코드 | `NTC_001` | `CNR_001`(없음), `CNR_002`(중복) |

  - 왜 `Corner` 가 아니고 `InstCorner` 인가: `src/domain/lookup.ts` 61줄에 이미 `Corner`(콤보용) 타입이 있다. 이름이 겹치면 import 할 때 헷갈린다.
  - 대분류 `mgmt`(종합관리)는 지금 있는 유일한 업무 대분류라서 골랐다. 다른 대분류(예: 기기관리)에 넣어야 하면 리드가 `types/screen.ts` `L1Slug` + `screens/l1.ts` 를 먼저 늘린다(CLAUDE.md "새 대분류").
  - 화면번호는 **어디에도 쓰지 않는다**(파일·라우트·주석 모두).

## 2. 파일 만드는 방법 (공통)

- **복사로 시작한다** — 빈 파일에서 쓰지 않는다. 예(Windows 탐색기 또는 PowerShell):

```powershell
Copy-Item Frontend\nh-atms-web\src\domain\notice.ts Frontend\nh-atms-web\src\domain\instCorner.ts
```

- 복사한 뒤 VS Code 에서 **바꾸기(Ctrl+H, 대소문자 구분 켬)** 를 이 순서로 한다(긴 것부터).
  1. `NoticeSearch` → `InstCornerSearch`
  2. `NoticeSave` → `InstCornerSave`
  3. `noticeApi` → `instCornerApi`, `noticeKeys` → `instCornerKeys`
  4. `Notice` → `InstCorner`, `notice` → `instCorner`
- 그다음 아래 표의 "줄 번호별 할 일" 대로 **컬럼과 키**를 바꾼다.
- 백엔드 폴더는 새로 만든다: `web/instcorner/{controller,dto,mapper,service}`, `mapper/instcorner/`, 테스트 `src/test/java/kr/co/nh/atms/web/instcorner/`.

## 3. [1단계] 계약 — `docs/07_API_계약.md` §8 추가

- 견본: 같은 파일 **91~110줄**(§3 공지사항).
- 할 일: 파일 끝(§7 뒤)에 아래를 붙인다. 프론트 타입·백엔드 DTO 는 **이 표와 글자 하나까지 같게** 만든다.

```markdown
## 8. 설치코너 관리 (`mgmt.instCorner`, 화면 경로 `/mgmt/inst-corner`, TB_SCRT_INST_PST)

| 메서드 경로 | 요청 | 응답 data | 권한 | 문구 |
|---|---|---|---|---|
| `GET /api/inst-corner` | `InstCornerSearch` | `PageResult<InstCorner>` | QRY | — |
| `GET /api/inst-corner/{ofcCode}/{instPstCode}` | — | `InstCorner` | QRY | 없음 404 `CNR_001` |
| `POST /api/inst-corner` | `InstCornerSave` | `InstCorner` | REG | `S002` / 중복 400 `CNR_002` |
| `PUT /api/inst-corner/{ofcCode}/{instPstCode}` | `InstCornerSave`(키는 경로 값) | `InstCorner` | UPD | `S003` / 없음 `CNR_001` |
| `DELETE /api/inst-corner/{ofcCode}/{instPstCode}` | — | `null` | DEL | `S004` / 없음 `CNR_001` |

​```ts
InstCornerSearch extends PageParams { ofcCode?: string; instPstNm?: string; useYn?: 'Y' | 'N' }
InstCorner extends Audit { ofcCode: string; kanm: string | null; instPstCode: string; instPstNm: string | null;
                           vendCode: string | null; opBgnTime: string | null; opEndTime: string | null; useYn: 'Y' | 'N' }
InstCornerSave { ofcCode: string; instPstCode: string /*1~3자*/; instPstNm: string /*필수 ≤80바이트*/;
                 vendCode: string /*필수 2자*/; opBgnTime?: string /*HHMM*/; opEndTime?: string /*HHMM*/; useYn: 'Y' | 'N' }
​```

- `INST_PST_CODE` 는 VARCHAR2(3) → 비교에 CAST 를 쓰지 않는다. `OFC_CODE` 는 CHAR(6) → `CAST(#{ofcCode} AS CHAR(6))`.
```

- 같은 파일 **§6 응답코드 표(146~158줄)** 에 두 줄 추가:

```markdown
| `CNR_001` | E | 설치코너를 찾을 수 없습니다. ({0}-{1}) |

```ts
import { api } from '../http';
import type { InstCorner, InstCornerSave, InstCornerSearch } from '@/domain/instCorner';
import type { PageResult } from '@/types/api';
import { compactParams } from '@/utils/object';

/**
 * 설치코너(`mgmt.instCorner`) API — API 계약 §8 (`/api/inst-corner…`).
 * 규칙: API 호출은 이 파일에서만, 쓰기 성공 문구는 서버가 보내고 http.ts 가 띄운다.
 * 화면의 onSuccess 는 `invalidateQueries({ queryKey: instCornerKeys.all })` 만.
 */
const path = (ofcCode: string, instPstCode: string) => `/inst-corner/${ofcCode}/${encodeURIComponent(instPstCode)}`;

export const instCornerApi = {
  list: (p: InstCornerSearch) => api.get<PageResult<InstCorner>>('/inst-corner', { params: compactParams(p) }),
  /** 1건. 없으면 404 CNR_001 */
  get: (ofcCode: string, instPstCode: string) => api.get<InstCorner>(path(ofcCode, instPstCode)),
  /** 등록 — 서버 문구 S002, 중복 CNR_002 */
  create: (body: InstCornerSave) => api.post<InstCorner>('/inst-corner', body),
  /** 수정 — 서버 문구 S003 */
  update: (ofcCode: string, instPstCode: string, body: InstCornerSave) => api.put<InstCorner>(path(ofcCode, instPstCode), body),
  /** 논리 삭제(USE_YN='N') — 서버 문구 S004 */
  remove: (ofcCode: string, instPstCode: string) => api.delete<null>(path(ofcCode, instPstCode)),
};

export const instCornerKeys = {
  all: ['instCorner'] as const,
  list: (p: InstCornerSearch) => ['instCorner', 'list', p] as const,
  detail: (ofcCode: string, instPstCode: string) => ['instCorner', 'detail', ofcCode, instPstCode] as const,
};
```

- `api.delete` 는 `src/api/http.ts` 99줄에 있다(기기정보 `src/api/endpoints/mcnInfo.ts` 가 같은 모양으로 쓴다).

    /** 본문 검사·정리 → 매퍼 파라미터. 키는 인자로 받은 값(등록 = 본문, 수정 = 경로) */
    private static InstCorner toCorner(InstCornerSave req, String ofcCode, String instPstCode) {
        if (req == null) throw new BusinessException("VAL_004");
        String nm = trimToNull(req.getInstPstNm());
        String vend = trimToNull(req.getVendCode());
        String useYn = trimToNull(req.getUseYn());
        if (nm == null || DbBytes.over(nm, InstCornerRules.INST_PST_NM_MAX_BYTES)) throw new BusinessException("VAL_001", "instPstNm");
        if (vend == null || vend.length() > 2) throw new BusinessException("VAL_001", "vendCode");
        if (!"Y".equals(useYn) && !"N".equals(useYn)) throw new BusinessException("VAL_003", "useYn");
        String bgn = trimToNull(req.getOpBgnTime());
        String end = trimToNull(req.getOpEndTime());
        if (!InstCornerRules.isHhmm(bgn)) throw new BusinessException("VAL_003", "opBgnTime");
        if (!InstCornerRules.isHhmm(end)) throw new BusinessException("VAL_003", "opEndTime");
        InstCorner c = new InstCorner();
        c.setOfcCode(OfficeCode.require(ofcCode));
        c.setInstPstCode(code(instPstCode));
        c.setInstPstNm(nm);
        c.setVendCode(vend);
        c.setOpBgnTime(bgn);
        c.setOpEndTime(end);
        c.setUseYn(useYn);
        return c;
    }

    /** 조회조건 정리(매퍼가 그대로 쓴다) */
    static void normalize(InstCornerSearchDto s) {
        s.setOfcCode(OfficeCode.norm(s.getOfcCode()));
        s.setInstPstNm(trimToNull(s.getInstPstNm()));
        String yn = trimToNull(s.getUseYn());
        if (yn != null && !"Y".equals(yn) && !"N".equals(yn)) throw new BusinessException("VAL_003", "useYn");
        s.setUseYn(yn);
    }

    private static String trimToNull(String v) {
        if (v == null) return null;
        String t = v.trim();
        return t.isEmpty() ? null : t;
    }

- `Notice` 를 한 번에 바꾸다가 `NoticeField`·`noticeColumns` 같은 이름이 반쯤 남는다 → 바꾼 뒤 파일에서 `otice` 로 검색해 0건인지 본다.
- 화면에서 `message.success(...)` 를 쓴다 → 쓰지 않는다. 성공 문구는 서버 `S002`·`S003`·`S004` 가 자동으로 뜬다.
- API 주위에 `try/catch` → 쓰지 않는다(오류 문구도 자동).
- SQL 에 `${}` → 금지. 항상 `#{}`.
- `INST_PST_CODE` 에 `CAST(… AS CHAR(3))` → **하지 않는다**(VARCHAR2 라서 CHAR 로 바꾸면 뒤 공백이 붙어 안 맞음). `TB_MCN_INFO` 와 조인할 때만 기기 쪽을 `RTRIM`(기기정보 XML 9줄 주석).
- 감사 컬럼 값을 직접 만든다 → `#{crtDtm}` 등만 쓴다(`AuditInterceptor` 가 채움).
- 화면번호(예: 숫자 ID)를 파일·주석에 쓴다 → 쓰지 않는다.
