## 0. 한눈에 보기

- **무엇**: 개발자(사람)와 각자의 Claude 가 **이 저장소 하나만 보고** 화면별 프론트·백엔드·DB·인프라를 같은 규칙으로 만들게 하는 "공통 뼈대 + 견본" 저장소.
- **어떻게 생겼나**: 실제로 빌드·실행되는 프로젝트 1벌.
  - 프론트: nh-atms 와 같은 버전(React 19 · antd 6 · Vite 7 · TS ES2020)
  - 백엔드: Spring Boot 3.5 · Java 21 · MyBatis, 모듈 2개(`atms-common` + `atms-web`), 패키지 `kr.co.nh.atms.web` 그대로
  - DB: Oracle(은행 개발 DB) 만. TO-BE `TB_` 테이블 기준.
- **화면 4개**
  1. **공통 모듈 화면** — 날짜·콤보·팝업·그리드·엑셀·권한·마스킹 등 "가져다 쓰는 부품"을 전부 실제 API 로 보여 주는 화면
  2. **공지사항** (`TB_NOTICE`) — 팝업형 등록/수정
  3. **기기정보** (`TB_MCN_INFO`) — 목록/편집 탭형
  4. **기기모델코드** (`TB_CO_MODEL`) — 기기사→모델 표 직접 편집(일괄 저장)형
  - 세 견본이 **서로 다른 CRUD 모양**을 하나씩 맡는다. 새 화면은 셋 중 비슷한 것을 복사해서 시작한다.
- **문서 3종**: 사람용 `README.md`, AI용 `CLAUDE.md`, 화면 에이전트 지시문 `agent-briefs/`.

## 1. 목적과 범위

### 1.1 넣는 것
- nh-atms 에 **이미 있는** 공통 요소(아래 §5·§6 표에 원본 경로를 적음)
- TO-BE 공통 테이블을 읽는 **공통 조회 API**(사무소·인원·기기사·모델·기기·코너·공통코드·시도/시군·휴일)
- 견본 화면 4개, 화면 → API → 서비스 → 매퍼 → SQL 끝까지
- 규칙 문서(README·CLAUDE.md·agent-briefs), 반입용 SHA-512 목록 만드는 방법

### 1.2 안 넣는 것
- 업무 화면(거래·저널·용역 등)과 그 API, 업무 전용 부품(`AlarmBell`, `StatusBitsPanel`, `ReconcileGrid`, `AtmStatusTag`, 원격명령 사용처 등)
- 데모·Vercel·inline 목, 옛 프론트 흔적
- nh-atms-server 의 배포킷(bin/conf/deploy) — **복사도 수정도 안 함**

### 1.3 "지어내지 않기" 표시 규칙
- 이 저장소의 모든 부품·API 에는 근거를 단다.
  - **[원본]** nh-atms 에 있는 것을 옮김 (원본 경로 표기)
  - **[TO-BE]** 20번 정본 테이블·컬럼을 그대로 씀
  - **[신규]** 원본에 없음 → §13 에서 사용자 승인을 받은 것만 만든다
  - **[잠정]** 정본·현업 답이 없어 임시 규칙 → `static` 메서드 1곳 + javadoc `잠정` + §14 질문 번호

### 5.2 응답·오류·메시지 [원본]
- 성공 `0000`, 조회는 `message:null`, 쓰기는 `ApiResponse.ok(data,"S002")` 처럼 코드로 문구.
- 예외 → HTTP: `BusinessException` 400, `NotFoundException` 404, `ForbiddenException` 403, `UnauthorizedException` 401, 나머지 500 `SYS_500`.
- 문구는 백엔드가 만들고 프론트는 그대로 띄운다. 소스에 한국어 문구 금지(`ApiMessageCodeGuardTest` 그대로 가져옴).
- `api-messages.tsv`: 공통 코드(`0000`, `S0xx`, `SYS_*`, `VAL_00x`, `AUTH_*`, `MNU_*`, `V001_20`, `E404` 등)만 옮기고, 견본용 코드를 새로 추가(§8 각 화면 표).
- `T_API_MESSAGE` 는 TO-BE 대응이 없다(H-074 대기) → 로더는 그대로 두고, 테이블이 없으면 시드만 쓴다(원본 동작).

### 5.3 사용자 식별 — 로그인 세션 (Q1 결정 → 2026-11-11 변경)

> **2026-11-11 사용자 결정: 로그인 필수.** 아래 "고정 사용자" 설명은 처음 결정(기록용)이다. 지금은
> `/login` 에서 개인번호·비밀번호로 로그인 → `LoginService` 가 HTTP 세션에 개인번호 → `SessionUserFilter`(옛 `FixedUserFilter`)가 요청마다 그 개인번호로 `CurrentUser` 를 채운다.
> 세션 없음 401 `ME_002`, 인사정보 없음 401 `ME_001` → 화면은 로그인 화면으로. 설정 `atms.fixed-user.per-no`·`atms.login.enabled` 는 없앴다.
> 비밀번호는 공통 테스트 비밀번호 1개(`InsaLoginVerifier.TEST_PASSWORD`, 잠정 Q-17), 로그인 화면 옆에 테스트 계정 6명(`src/screens/login/testAccounts.ts`). 계약 §7.

- TO-BE 정본에는 **사용자·비밀번호 테이블이 없다.** 사람 정보는 `TB_INSA`(개인번호 `PER_NO`), 권한은 `TB_SCR_AUTH`(부서+사무소+개인번호 → `AUTH`).
- 결정: **로그인 화면·토큰 없이 고정 사용자**로 돈다.
  - 설정 `atms.fixed-user.per-no` 에 개인번호 1개(이 저장소 `application-local.yml`·`application-jeus.yml` 에는 `CHANGE_ME`, 실제 값은 `D:\local-db.yml` 처럼 저장소 밖에서 넣을 수 있게).
  - 요청마다 `FixedUserFilter`(신규, `web/common/auth`)가 그 개인번호로 `CurrentUser` 를 채운다. 이름·사무소·부서는 `TB_INSA`, 권한코드는 `TB_SCR_AUTH`(승인상태 유효·만료일 안 지난 행), 화면별 권한은 `TB_SCR_AUTH_MENU`. 결과는 짧게 캐시.
  - 개인번호가 비어 있거나(`CHANGE_ME` 포함) `TB_INSA` 에 없으면 모든 `/api/**` 가 401 `ME_001` + 문구로 알려 준다(조용히 관리자 취급하지 않음). `SYS_401` 은 보안 필터의 "사용자 정보 없음"용으로만 남는다(문구에 "로그인" 없음).
- `GET /api/me` → `{perNo, name, samuso, samusoName, deptCode, ofcCode, kanm, auth, adminYn}` (`adminYn` 'Y'|'N', 계약 §1 `Me`) — 프론트 머리글·기본 사무소에 씀.
- 감사 컬럼 `CRT_CMENO`·`LS_CMENO`(개인번호) 는 이 고정 개인번호로 채워진다.
- 원본의 JWT·SSO·로그인 코드(`auth/*`, `security/jwt`, `security/sso`)는 **가져오지 않는다**. 나중에 SSO 를 붙일 자리는 `FixedUserFilter` 한 곳(문서에 "SSO 붙일 때 바꿀 곳"으로 표시).
- 프론트: 로그인 화면·토큰 갱신·세션 타이머·무조작 로그아웃은 뺀다. `useAuthStore` 는 `/api/me` 결과만 담는다. `http.ts` 의 401 재시도(refresh) 부분은 제거.

### 5.6 감사 컬럼 자동 채움 [신규 — 21지침 §3 "web/common 공통 처리로 채운다"]
- 원본에는 공통 처리가 **없다**(매퍼마다 손으로 씀). 21 지침이 공통 처리를 요구하므로 만든다.
- 방법: DTO 가 `Auditable`(필드 `crtDtm, crtCmeno, lschgDtm, lsCmeno`)을 구현하면 MyBatis `Interceptor`(Executor.update)가 INSERT 면 4개, UPDATE 면 2개를 채운다.
  - 일시: `Dates.now14()` (`YYYYMMDDHH24MISS`, CHAR(14))
  - 개인번호: `CurrentUser.perNo()`, 로그인 없으면 시스템 ID 상수 1곳(H-071 대기)
- 매퍼는 `#{crtDtm}` 등을 쓰기만 한다. INSERT/UPDATE 구분은 MyBatis `SqlCommandType`.

- **SQL 작성 규칙(Q5)**: 키워드·테이블·컬럼 모두 대문자, 컬럼은 정본 이름 그대로 `SELECT OFC_CODE, KANM FROM TB_OFC_REG_MGT`. 별칭으로 이름을 바꾸지 않는다(이름 붙이기 조인 값만 정본에 없는 이름이 필요할 때 `AS` + 대문자, 예 `AS SRC_NM`). CHAR 패딩 제거가 필요하면 `RTRIM(INST_PST_CODE) AS INST_PST_CODE`. 자바·JSON 은 `map-underscore-to-camel-case` 로 `ofcCode`.
- CHAR/VARCHAR2 섞임: `OFC_CODE` CHAR(6) vs `TB_OFC_RAW.SAMUSO` VARCHAR2(6) 등은 21지침 §5 대로 `CAST(#{v} AS CHAR(n))`/`TRIM`. 인덱스 쪽 컬럼은 가공하지 않는다.
- 사무소코드는 `OfficeCode.norm/require`: 숫자 1~6자리는 앞자리 0 채움(6자리), 숫자 아님·7자리 이상은 400 `VAL_003`(ofcCode), 필수인데 비면 `V001_20`.

## 7. DB 설계

### 7.1 이 저장소가 쓰는 TB_ 테이블

| 테이블 | 용도 | 읽기/쓰기 |
|---|---|---|
| `TB_NOTICE` | 공지사항 견본 | 읽기·쓰기 |
| `TB_MCN_INFO` | 기기정보 견본, 기기 콤보·팝업 | 읽기·쓰기 |
| `TB_CO_MODEL` | 기기모델코드 견본, 모델 콤보 | 읽기·쓰기 |
| `TB_CO_CODE_MST` / `TB_CO_CODE` | 공통코드 콤보 | 읽기 |
| `TB_SCR_MENU` / `TB_SCR_AUTH_MENU` / `TB_SCR_AUTH` | 메뉴·권한 | 읽기 |
| `TB_INSA` | 로그인 사용자·인원 콤보/팝업 | 읽기 |
| `TB_OFC_REG_MGT` | 사무소 콤보/팝업(사무소명 KANM) | 읽기 |
| `TB_SCRT_INST_PST` | 코너 콤보 | 읽기 |
| `TB_NMS_SRC` | 기종명(SRC_NM) | 읽기 |
| `TB_CO_SIDO` / `TB_CO_SIGUN` | 시도·시군 콤보 | 읽기 |
| `TB_NMS_HDAY` | 휴일 표시 | 읽기 |
| `T_API_MESSAGE` (T_ 유지, H-074) | 응답 문구 덮어쓰기 | 읽기(없으면 시드) |
| `T_USER_ACTION_LOG` (T_ 유지, H-074) | 행위이력 | 쓰기(§13 Q7) |

### 7.2 컬럼 주의 (정본 그대로 쓰면서 조심할 것)
- `TB_NOTICE.WRT_DATE` 는 **DATE**(원본이 정한 예외). 나머지 날짜는 CHAR 문자열.
- `TB_NOTICE.NAME` VARCHAR2(10), `TB_INSA.NAME` VARCHAR2(10) — BYTE 기준이면 한글 5자(KO16MSWIN949, 2바이트) → 입력 검증에 바이트 길이 검사 넣음, §14 Q-07.
- `TB_MCN_INFO.VEND_CODE` VARCHAR2(2) vs `TB_SCRT_INST_PST.VEND_CODE` VARCHAR2(2) vs 다른 테이블 CHAR(3) → 조인 전 코드 체계 확인(21지침 §5).
- `TB_MCN_INFO.OP_TYPE`=운영구분(365), `INOUT_TYPE`=정내외(I,O) — 20번 §4.2 사전과 뜻이 **반대로** 적혀 있음 → 테이블 정의(속성명)대로 쓰고 §14 Q-04.
- `TB_CO_MODEL` PK 는 3개(`VEND_CODE+MCN_TYPE+MODEL_CODE`). 원본 `T_ATM_MODEL` 은 MODEL_CD 1개 → 화면·API 키를 3개로.
- 물리 FK 없음 → "다른 테이블에서 쓰는 중이면 삭제 금지" 같은 검사는 서비스에서.

### 7.3 DDL·시드
- `db/ddl/*.sql`: 20번 CSV 에서 **생성기로** 만든다(손으로 안 고침). 테이블·컬럼·타입·PK·NULL 정본과 똑같이, `COMMENT ON` 포함, FK 없음.
- `db/seed/*.sql`: 견본 확인용 데이터(MERGE … WHEN NOT MATCHED, 다시 돌려도 안전). 메뉴·권한 시드는 견본 4화면만.
- 은행 개발 DB 에 이 TB_ 테이블들이 **이미 있는지 모른다** → §13 Q10. 있으면 DDL 은 참고용, 시드만 적용.
- nh-atms 의 `V1.6.x` 번호 체계와 겹치지 않게 이 저장소 파일에는 버전 번호를 붙이지 않는다(적용 기록은 Q10 답에 따라).

## 8. 화면 설계

> 공통: `PageFrame` → `SearchForm` → `ResultHeader`(+엑셀·버튼) → `DataGrid`. 조회는 [조회] 버튼, 권한은 §5.5, 문구는 서버.

### 8.1 공통 모듈 화면 (`sample.commonModules`)
- 목적: "이 부품 쓰면 이렇게 된다"를 **실제 API** 로 보여 주는 카탈로그. 탭마다 [코드 보기] 로 쓰는 법(짧은 예시)을 보여 준다.
- 탭 구성
  1. 날짜 — 단일일자, 기간(+최대 31일 검증), 일·월 기간, 기준월, 년도, ◀▶ 일자, 시각 범위, 빠른선택, 휴일 표시
  2. 콤보 — 사무소(+코드입력·팝업) → 기기 → 코너 종속, 기기사 → 모델 종속, 사무소 → 인원 종속, 공통코드, 있는 값, 시도 → 시군, 사용여부
  3. 팝업 — 사무소·인원·기기 검색 팝업, 상세 팝업, 입력 팝업(검증 규칙 전종), 주소, 원문 열람 사유, 결재 요청/책임자 승인
  4. 표 — DataGrid G1/G2/G3, 컬럼 헬퍼 전종, 선택·더블클릭, EditableGrid, MasterDetail, Matrix, 행 명령 버튼
  5. 출력 — 엑셀 다운로드, 인쇄 레이아웃, 마스킹/원문 열람, 첨부파일
  6. 권한·메시지 — 내 권한 5개 표시, 권한별 버튼 흐림/숨김, 서버 성공·오류 문구, 하단 메시지 라인, 확인창 문구
- 백엔드: §5.7 공통 조회 API 만 씀(전용 API 없음). 원문 열람 시연은 원본 `/api/std/unmask` 처럼 데모 응답(로그 테이블 없이).

### 8.2 공지사항 (`sample.notice`, `TB_NOTICE`) — "팝업형 CRUD" 견본
- 조회조건: 작성일 기간(WRT_DATE, 기본 최근 1개월, 최대 1년), 사무소(OfficeSelector, 기본 로그인 사무소, 선택), 작성자(인원 콤보, 사무소 종속), 검색구분(전체/제목/내용/작성자)+검색어
- 그리드(G1): 순번, 번호(NO), 제목, 사무소(코드+명), 작성자(NAME), 작성일(WRT_DATE), 조회수(VISIT)
- 버튼: 조회(QRY) · 엑셀(QRY) · 인쇄(QRY) · 등록(REG) · 수정(UPD, 1건 선택) · 삭제(DEL, 다건 선택+확인창)
- 팝업
  - 상세 보기(행 더블클릭) — 열 때 조회수 +1
  - 등록/수정 — 제목(필수, 200바이트), 내용(필수, 4000바이트), 사무소(기본 로그인 사무소). 작성자·개인번호는 로그인 사용자로 자동(수정 불가)
- API
  | 메서드 경로 | 동작 | 문구 코드 |
  |---|---|---|
  | `GET /api/notice` | 목록(페이징) | — |
  | `GET /api/notice/{no}` | 1건 + 조회수 증가 | 없으면 `NTC_001`(원본 코드) |
  | `POST /api/notice` | 등록 | `S002` |
  | `PUT /api/notice/{no}` | 수정 | `S003` |
  | `POST /api/notice/delete` `{nos:[]}` | 다건 삭제 | `S005`({0}건) |
- SQL 요점: 번호 채번 `NVL(MAX(NO),0)+1`(원본 선례, [잠정] §14 Q-02), 삭제는 물리 삭제(정본에 사용여부 없음), 감사 컬럼은 공통 처리.
- 정본에 없는 원본 기능(분류·중요공지·첨부·게시기간)은 **넣지 않는다** → §14 Q-02 로 질문.

### 8.3 기기정보 (`sample.mcnInfo`, `TB_MCN_INFO`) — "목록/편집 탭형" 견본
- 조회조건: 사무소(필수, `OfficeCode.require`), 기번, 기기사, 기기유형(KOM_TYPE), 운영구분(OP_TYPE), 정내외(INOUT_TYPE), 사용여부(기본 Y)
- 그리드(G2): 순번, 사무소, 기번, 코너(코드+명), 기종(SRC+명), 기기유형, 기기사, 운영구분, 정내외, 장소특성, 사용여부, 최종변경일시·변경자
- 탭: [목록] / [등록·수정] (`ListEditTabs`). 편집 탭에서 PK(사무소·기번)는 수정 불가.
- 입력: 사무소(팝업), 기번(숫자 3자리), 코너(사무소 종속 콤보), 기종(SRC, `TB_NMS_SRC` 콤보), 기기유형·기기사·운영구분·정내외·장소특성(코드표가 정해지기 전에는 "있는 값 콤보"+직접입력, [잠정]), 사용여부
- 버튼: 조회·엑셀·등록·수정·삭제(사용여부 'N' 으로 바꾸는 방식, §13 Q11)
- 팝업: 기기 검색(`McnSearchModal`) — 조회조건 기번 칸 🔍
- API: `GET /api/mcn-info`, `GET /api/mcn-info/{ofcCode}/{mcnNo}`, `POST /api/mcn-info`(중복 `MCN_002`), `PUT /api/mcn-info/{ofcCode}/{mcnNo}`, `DELETE /api/mcn-info/{ofcCode}/{mcnNo}` — 새 코드 `MCN_001`(없음), `MCN_002`(이미 있음)

### 8.4 기기모델코드 (`sample.mcnModel`, `TB_CO_MODEL`) — "표 직접 편집·일괄 저장형" 견본
- 원본 기기사·모델 관리 화면(`MasterDetailGrids` + `EditableGrid` + `BatchChanges`) 모양을 따른다.
- 왼쪽: 기기사 목록(조회조건: 기기사), 오른쪽: 선택한 기기사의 모델 표(기기구분·모델코드·모델명, 직접 편집)
- 버튼: 조회 · 엑셀 · 행추가(REG) · 행삭제(DEL) · 저장(UPD — 추가·수정·삭제를 한 번에) · 취소
- 검증: 키 3개 필수, 같은 기기사 안 (기기구분, 모델코드) 중복 금지, 모델명 80바이트
- API: `GET /api/mcn-model?vendCode=&mcnType=&q=`, `POST /api/mcn-model/batch`(`BatchChanges`) → `S001` / 새 코드 `MDL_001`(없음), `MDL_002`(중복) — 원본 `ATM_MODEL_001/002` 는 T_ 기준 문구라 따로 둠
- 삭제 보호: 정본 `TB_MCN_INFO` 에 모델 컬럼이 없어 "사용 중 모델" 검사를 할 근거가 없음 → 검사 안 함, §14 Q-06

## 10. 인프라·반입

- **nh-atms-server 는 손대지 않는다.** 이 저장소는 배포킷과 같은 폴더 이름·빌드 명령을 쓰게 맞춰서, 킷을 고치지 않고 빌드되도록 한다.
- JEUS 배포용 설정(`-Pjeus` WAR, `jeus/web.xml`, `jeus-common.yml` JNDI `dsATMS01`)을 **이 저장소에 복사해 둘지**는 §13 Q3. (복사만, server 파일은 그대로)
- 반입: 원본 규칙 그대로 — `.git` 빼고 저장소 통째, 압축 안의 압축 금지, `tools/sha512-list.sh` 로 `SHA512SUMS.txt`(git ls-files 기준 파일별), 바이너리(`gradle-wrapper.jar`, 이미지)는 별도 승인. npm 은 새 패키지가 없으므로 기존 캐시로 `npm ci --offline`.
- 서버 명령은 한 줄에 하나, `sudo`/`su` 없음.
