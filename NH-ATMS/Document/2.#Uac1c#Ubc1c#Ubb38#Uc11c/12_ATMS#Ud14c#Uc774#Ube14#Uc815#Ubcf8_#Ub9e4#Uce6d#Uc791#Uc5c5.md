## 2.4 ⭐설계방침: 저널 기반 정보는 "현행 구축 스키마" 사용 (확정)

> 사용자 확정(2026-06-02): **장애·시재·저널·기기현황** 등 **ATM Agent가 발송하는 저널로 알 수 있는
> 정보**는, AS-IS 588 테이블을 그대로 옮기지 않고 **이번 프로젝트에서 이미 구축한 스키마를 사용**한다.

### 2.4.1 핵심 데이터 흐름

```
[ATM 단말] ──저널 발송──> [ATM Agent] ──수신/적재──> [ATMS DB: 현행 구축 스키마]
                                                          │
                                  ┌───────────────────────┼───────────────────────┐
                                  ▼                        ▼                        ▼
                            기기별 장애현황            기기별 시재현황           저널 원문 조회
                          (저널 이벤트 집계)          (입출금 누적)            (이미지/데이터)
```

- **저널이 1차 원천(Source of Truth)**. 장애/시재/기기상태는 저널을 **기기별로 집계·표시**한 뷰.
- 즉 AS-IS의 수많은 거래/상태/통계 테이블을 다 만들 필요 없음 → **저널 + 파생집계**로 커버.

### 2.4.2 저널로 커버되는 업무 ↔ 현행 구축 스키마 매핑

| 업무영역 | 저널에서 얻는 정보 | 사용할 현행 스키마(이미 구축) |
| --- | --- | --- |
| **저널 원문** | 거래/운영 저널 원문, 이미지, 데이터 | `T_JOURNAL`, `T_JOURNAL_DATA`, `T_JOURNAL_IMAGE`, `T_JOURNAL_FOOTNOTE`, `T_JOURNAL_ERROR`, `T_TRANSACTIONJOURNAL`, `T_OPERATIONJOURNAL` |
| **기기현황** | 기기별 상태/유닛/카세트/에이전트 | `T_ATMMONITOR`, `T_ATMSTATUS`, `T_ATMUNITSTATUS`, `T_AGENTSTATUS`, `T_CASSETTESTATUS`, `T_ATMSTOPHISTORY` |
| **장애** | 저널 에러 이벤트 → 기기별 장애 | `T_FAULTMANAGEMENT`, `T_FAULTANALYSIS`, `T_FAULTRATEMANAGEMENT`, `T_JOURNAL_ERROR` + `T_DEVICEFAULTHIST`(V1.3.0) |
| **시재** | 입출금 누적 → 기기별 시재 | `T_CASHTRANSACTION`, `T_ADDCASH`, `T_ADDCHECK`, `T_CASSETTESTATUS`, `T_DAYTOTAL`, `T_TRANSACTIONDAILYTOTAL` |
| **거래상태/망/데몬** | 저널 부가 상태정보 | `T_TRANSTATUSMSG`, `T_NETWORKSTATUS`, `T_DAEMONSTATUS`, `T_UNFINISHEDCOUNT` (V1.2.9) |
| **SLA/가동율** | 장애·미가동 집계 → 평가 | `T_SLAGRADE`, `T_CORNERSLA`, `T_DEVICEOPRATEHIST`, `T_DEVICEFAULTHIST`, `T_NONOPREASON` (V1.3.0) |

### 2.4.3 그래서 PDF 588 테이블의 처리 원칙

| PDF 테이블 성격 | 처리 방침 |
| --- | --- |
| 저널로 도출 가능한 **거래/상태/통계** (`자동화기기_`, `ILM_` 계열) | **신규 생성 안 함**. 저널 + 현행 스키마 + 파생집계로 대체 |
| 저널과 무관한 **운영관리** (시재계획/현송/SLA/용역료/평가, `자동화기기관리_`) | 필요한 것만 **신규 설계** (요건확정 후). 일부는 V1.3.0 선반영 |
| **마스터/코드/권한** | 현행 구축 스키마 사용 (`T_BRANCH`, `T_ATM`, `T_CODE`, `T_USER`, `T_AUTH` 등) |

> ✅ **결론**: 대조표 §13의 `컬럼확보=Y`(저널/거래 계열)는 대부분 **현행 스키마로 흡수** →
> 실제 신규 설계 대상은 `컬럼확보=N`의 **운영관리 계열 일부**로 좁혀짐.
> 화면 매칭도 이 **운영관리 계열(N)** 에 집중하면 됨.

## 3. 참고: 현행 배포 48종과의 관계

- 본 PDF 정본 목록과 현행 48종(11_ 문서)은 **상당수 1:1 대응**될 것으로 예상
  (예: PDF `I_USER`≈`T_USER`, `BATCHJOBLOG`≈`T_BATCHHISTORY`, `UMS메시지`≈`T_SMSSENDDATA`)
- 대응 안 되는 PDF 테이블 = 신규 설계 대상
- 현행 48종 중 PDF에 없는 것 = ATMS 신규(웹/권한 등) 또는 명칭만 상이
