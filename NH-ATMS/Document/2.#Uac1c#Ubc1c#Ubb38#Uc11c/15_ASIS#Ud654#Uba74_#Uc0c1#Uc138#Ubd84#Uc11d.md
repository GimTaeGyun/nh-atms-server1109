## 0. 화면 공통 프레임 (전 화면 공통 — 분석 시 제외 영역 식별용)

AS-IS는 차세대 통합UI 틀 안에 ATMS 화면이 내장된 구조다. **TO-BE에서 우리가 구현할 영역은 본문(중앙 패널)뿐**이고, 아래는 차세대/인스웨이브가 제공한다.

| 영역 | 내용 | TO-BE 처리 |
|---|---|---|
| 상단 메뉴바 | 16여신심사 18전자창구 19신금고 21수납장표 **26자동화기기** 27방카 30NH농협카드 33경영관리 35환원자료 38자주기업평가 39기관관리 41채권관리 | ❌ 차세대 통합UI 영역 (회의 사전#8: 별도화면+통합로그인 링크) |
| 좌측 패널 | 화면목록/즐겨찾기/저장화면/도구, "농축협 미완료거래(10-0500)" | ❌ 통합UI 영역 |
| 우측 패널 | 마케팅/CARD 배너, 고객성장 5대 실천과제 광고 | ❌ **제외** (TO-BE 불필요) |
| 하단 탭바 | 열린 화면 탭(자동:0000, 자동:1001 …) | ❌ 통합UI 멀티탭 |
| 상태바 | 접속/서버1/착신/버전(v.1.0.x.x)/수정/한글/일시/IP/프린터 | ❌ 통합UI |
| **중앙 본문** | **조회조건 + 그리드 + 버튼** | ✅ **우리 구현 영역** |

> 분석은 이하 **중앙 본문**만 다룬다. (우측 광고·하단 공지 배너 등은 무시)

## 1. 거래조회 1000번대 (AP origin → 저널 재구현)

> 결론: 1000~1008은 모두 **거래저널(71) 조회**다. TO-BE에서 **`시재관리 > 거래내역조회` 1개로 통합**(거래종류·자행/타행·계좌/카드/명세표를 필터로). 1020/1301만 별도(2차파기).

### 1000 — 특정(건별) 거래 조회

- **조회조건**: 거래일자(From~To), 처리유형 라디오 4종 = `자행 계좌번호 / 타행 계좌번호 / 카드 번호 / 명세표 일련번호`, 계좌번호 입력
- **결과 탭**: `농협은행+농축협 / 농협은행 / 농축협` (소속 구분)
- **그리드 컬럼**: 순번 · 거래종류 · 거래일자 · 사무소/기번/일련번호 · 개설계좌(은행/예금주명/계좌번호) · 수취계좌(은행/예금주명/계좌번호) · 거래금액 · 수수료
- **상호작용**: 행 더블클릭 → 상세내역, 인쇄
- **성격**: 계좌/카드/명세표 1건을 **키로 콕 집어 추적**하는 건별 조회 (단건 추적용)

### 1001 — 입금/출금 거래

- **조회조건**: 사무소(드롭다운+돋보기검색) + 기번, 거래일자 From~To (각 `합계후/합계전` 구분), 조회항목 체크박스 = `자행출금·자행입금·타행출금·타행입금·신용카드출금`
- **버튼**: 조회, 출납과잉금, 거래상태별 집계
- **그리드 컬럼**: 순번·거래종류·거래일자·기번·일련번호·계좌은행/예금주명/계좌번호/카드번호·거래금액·수수료·거래상태·합계구분
- **성격**: 특정 기기(사무소+기번)의 **거래 목록** 조회. `합계전/합계후` = 마감집계 기준 구분이 핵심

### 1003 — 공과금/납부 거래

- **탭**: `장표납부(수납장표 마감대상)` / `조회납부(즉시이체성 거래)` / `전체`
- **그리드**: 순번·거래종류·거래일시·기번·일련번호·개설계좌(은행/예금주명/계좌번호)·거래금액·**장표건수·수납결과**·합계구분
- **성격**: 지로/공과금 수납. **장표납부=수납장표 마감대상**(21수납장표 메뉴 연계), 조회납부=즉시이체. 수납결과/장표건수가 특화 컬럼.

### 1004 — 신용카드 거래

- **탭**: `전체` / `단기카드(현금서비스)` / `장기카드(카드론)` / `기타(해외카드/선결제/기프트)`
- **그리드**: 순번·**카드구분**·은행명·**거래유형**·거래일자·카드번호·기번·일련번호·거래금액·거래상태·합계구분
- **성격**: 카드 거래. 단기(현금서비스)/장기(카드론)/기타로 분류 → 카드구분 코드 필요.

### 1005 — 수표입출금 거래조회

- **탭**: `출금+입금` / `출금거래` / `입금거래`
- **그리드**: 순번·거래종류·거래일자·기번·일련번호·계좌정보·거래금액·수수료·거래상태·**수표정보**·합계구분
- **성격**: 수표 매체 거래. **수표정보(매수/번호/금액)** 컬럼이 특화. TO-BE 수표거래조회 별도 유지.

### 1006 — 무통장/무카드 거래

- **조회조건**: 거래일자(합계후/합계전), 사무소+기번 / `출력` 버튼
- **그리드**: 순번·거래종류·거래일자·기번·일련번호·계좌은행/예금주명/계좌번호·거래금액·수수료·거래상태·합계구분
- **성격**: 매체 없는(무통장/무카드) 입금거래.

### 1007 — 통장 기장 거래

- **조회조건**: 거래일자, 입력구분(`자행 계좌번호` / `기기번호`), 계좌번호
- **그리드**: 순번·거래일자·취급점·기번·일련번호·계좌번호·**기장LINE·통장페이지·통장발급번호**·거래상태
- **성격**: 통장기장(미정리내역 기장). 통장 물리정보(LINE/페이지/발급번호)가 특화.

### 1008 / 1501 — 외화 입/출금 거래

- **조회조건**: 사무소+기번, 거래일자(합계후/합계전) / 조회·출납과잉금·거래상태별집계
- **그리드**: 순번·거래종류·거래일시·기번·일련번호·계좌은행/계좌번호/카드번호·**거래금액(원)·거래금액(외화)·통화**·거래상태·합계구분
- **성격**: 외화 ATM 거래. **원화/외화/통화** 3컬럼이 핵심. 1501은 동일 화면이나 하단 **QueryData 패널**(사무소코드/기기번호/거래일자/거래시간/처리유형/Query File Base/Target Table/Target DB) 노출 — 쿼리기반 추적용.

### 1020 / 1301 — 거래내역 2차 파기 조회 ★개인정보 보호

- **상단 안내**: "조회가능기간 0009.00.00 ~ 0005.00.00" (≈ **5~9년 경과 파기보관분**)
- **보호 문구**: *"해당 정보는 보호 조치되었습니다. 단계별 조회사유입력 및 책임자 승인 후 조회 가능합니다."*
- **조회조건**: 거래일자 From~To, 처리유형(1020=자행/타행/카드/명세표 4종, 1301=자행/카드/명세표 3종), 계좌번호
- **승인 영역**: `조회사유 선택` 드롭다운 + `상세사유` 텍스트 + (1301)`승인 요청` 버튼
- **그리드**: 일반조회 컬럼 + **`SCR_NO_CODE`**(보호/추적 코드)
- **성격**: 장기보관(2차파기) 데이터의 **사유기재 + 책임자 승인 후 조회**. 1301은 명시적 승인 워크플로.

### 1091 — 1차파기대상 조회 내역 (영상정보 열람 이력) ★감사로그

- **조회조건**: 사무소, 조회일자(From~To) / 조회·인쇄
- **그리드(영상정보 열람 이력)**: 조회요청일시 · 조회화면 · **조회일자(거래일) 시작/종료** · 조회사유 · **조회자 · 승인자**
- **성격**: 파기대상/영상정보를 **누가·언제·왜 열람했는지** 남기는 **감사로그 화면**. 4000번대 저널이미지 접근통제와 동일 맥락. → 개인정보보호법 대응 필수.

### 1099 — 파기정보 보호조치자료 접근안내 (파기 단계별 접근통제 정책)

- **안내 내용**: "해당 정보는 보호조치되었습니다. 조회사유입력 및 책임자 승인 후 조회 가능"
  - **1차파기: 거래일 90일 이후, 책임자 1인 승인 필요**
  - **2차파기: 거래일 5년 이후, 책임자 2인 승인 필요**
  - 책임자 KEY-IN 시 인증 후 승인요청
- **조회사유 선택**: 법원자료제출 / 조세관련제출 / 본인요청 / 민원관련조회 / 기타
- **성격**: 거래데이터 **파기 단계별 접근통제 정책의 게이트 화면**. → 보존/파기 정책 + 승인단계 설계의 원천.

### 1100 — 출납과잉금 예상거래 / 자금반환등록 ★자금반환 업무

- **탭**: `출납과잉금 예상거래`(센터수신정보만 표기) / `자금반환등록내역`
- **그리드**: 순번·거래종류·거래일자·기번·일련번호·계좌은행/예금주명/계좌번호/카드번호·거래금액·수수료·거래상태·**자금반환등록·메모**
- **자금반환 유의사항**: 타행지급거래만 가능 / 미수취일 다음날부터 등록(영업일 09~17시) / 반환금액=지급거래액 전액+취급점수수료(450원) / **책임자 1인 승인** / 등록 후 30분 이내 처리 / 결과는 `14(대외대행)_8326 자금반환` 화면 / NH머니카드는 `30(NH농협카드)_4410`
- ※ 입금장애는 `4000 전자저널 // 2301 장애명세서` 확인
- **성격**: ATM 미수취(과잉금) 거래의 **자금반환 등록 업무**. 외부(대외대행/카드) 연계.

### 1200 — 자금반환 등록내역 (반환 결과 집계)

- **조회조건**: 사무소, 등록일자 / 조회·출력
- **집계**: `등록정상` / `등록정정` / `처리중` × (건수/금액)
- **그리드**: 순번·거래일자·고유번호·계좌은행/계좌번호·거래금액·수수료·거래구분·구분
- **성격**: 1100 자금반환의 **등록결과 모니터링/집계**.

### 1300 — 전체거래 조회 (Administrator Only) ★기술필드 노출

- **조회조건**: 사무소+기번, 거래일자(합계후/합계전), `정상 선조회 거래 포함`, `정상(8처리중)`·`불능` 체크
- **그리드**: 순번·SCR·거래종류·거래일자·기번·일련번호·입력매체·매체정보·거래금액·수수료·거래상태·Cd·수취계좌정보·합계구분·**SVR · HOST_ID · PRC_STAT · PRC_RUT · FEE_EXEM · DAV**
- **성격**: 관리자전용 전체거래(정상+불능+처리중). **거래의 기술/운영 필드**(서버·호스트·처리상태·라우팅·수수료면제·DAV)가 그대로 노출 → **거래/저널 테이블 설계 시 보유해야 할 운영컬럼 카탈로그**. 디버깅·정산대사용.

## 2. 마감처리 2000번대 (AP origin → 기기/마감 데이터 기반 신규 구현)

> 결론: 2000번대는 ATMS **마감 핵심**이다. 개국/합계 원격명령(2000) + 마감집계 조회(2101/2102) + 전자결재(2200/2201). 전부 **신규 구현 대상**(저널대체 아님). TO-BE `마감처리` 대분류.

### 2000 — 개국/합계 등록 (원격 기기 명령)

- **입력조건**: 사무소(드롭+돋보기) + 기번, `합계가능시각`(16:00 표시), `현서비스각`(00:00)
- **처리구분 라디오 5종** ★핵심:
  1. `강제개국등록` (+ 사유 드롭다운)
  2. `강제합계등록`
  3. `원격합계등록후 기기 OPEN`
  4. `원격합계등록후 기기 DOWN`
  5. `사용중지해제`
- **버튼**: 실행
- **실행결과 영역**: 실행일시 · 사무소 · 기번 · 실행결과(텍스트)
- **성격**: ATMS → 기기로 **원격 운영명령 전송** + 결과 로깅 (조회 아닌 제어 화면)

### 2101 — 집계내역/합계상태 조회 ★마감집계 구조

- **조회조건**: 사무소 + 기번, 거래일(±30일 이내 조회 가능)
- **좌측**: 기기 리스트(No) + `합계상태조회` 버튼
- **센터집계분 그리드** (행 × 열 매트릭스):
  - **행**: 현금지급 · 수표지급 · 현금입금 · 수표입금 · (농협수표) · (타행수표)
  - **열**: `전일합계후` · `당일합계전` · `합계` · `당일합계후` (각 건수/금액)
- **기기집계분 그리드**: 행(현금지급/수표지급/현금입금/수표입금) × 동일 열
- **안내**: "자출납 정산표는 [06(회계)-3510] 화면에서 조회" → **회계(계정계) 연동 경계** 명시
- **성격**: 마감 시점별(전일합계후→당일합계전→당일합계후) 누적 집계 상태

### 2102 — 외화 합계 상태조회

- 2101과 동일 구조의 **외화 버전**. △ 외화 ATM 운영 시.

### 2200 — 마감장표 전자결재(ATM) ★전자결재 워크플로

- **조회조건**: 사무소 + 거래기준일자, 기준범위 `전일 합계후 ~ 당일 합계전`
- **마감자료 목록 그리드**: 화면번호(26-1005/1006/1100/2101 하이퍼링크) · 마감자료명 · 자료확인(체크박스 + `① 내역 확인`) · 맨아래 `전체 내역 확인`
  - 자료 예: 수표입금거래 / 수표입금·거래상태별 집계표 / 무통장·무카드거래 / 출납과잉금 예상거래 / 입출금 합계내역 조회표
- **결재 버튼**: `② 결재(팀원)` `③ 결재(팀장)` — *"클릭 시 환원자료로 정보가 전송됩니다"*
- **결재정보 영역**: 구분(팀원/팀장) × 개인번호 · 성명 · 결재일시
- **조작순서**: 팀원 = ①내역확인→②결재(팀원), 팀장 = ①내역확인→③결재(팀장)
- **주의문**: "기기에서 집계한 참고자료, 반드시 실제 시재금/회계 정보와 확인" → **참고용, 원장정산은 계정계**

### 2201 — 일마감 전자결재

- **2200과 거의 동일** (마감자료 목록·결재버튼·조작순서 동일). 차이는 결재정보 영역 표시 방식뿐.
- → **TO-BE에서 2200/2201 단일 화면 통합** 가능.

### 2000번대 → TO-BE 매핑 / 설계 시사점

| AS-IS | TO-BE | 성격 | 데이터원천 |
|---|---|---|---|
| 2000 | 마감처리>개국/합계등록 | 원격 제어명령 | 기기명령 전송 + 결과로그 |
| 2101 | 마감처리>집계내역(합계상태) | 마감집계 조회 | 기기 마감전문 집계 |
| 2102 | 마감처리>집계내역(외화탭) | 외화 마감집계 | 〃 외화 |
| 2200/2201 | 마감처리>마감 전자결재 | 결재 워크플로 | 집계 + 결재이력 |

**핵심 설계 도출:**
1. **마감 시점 모델**이 도메인을 관통: `전일합계후 → 당일합계전 → (합계) → 당일합계후`. 거래조회(1001)의 `합계전/합계후`와 **동일 축** → 거래·집계·결재가 이 시점키로 묶인다.
2. 2000은 **원격 제어**(개국/합계/OPEN/DOWN/중지해제) → atms-if-internal 기기명령 + 명령이력 테이블 필요.
3. 전자결재는 **팀원→팀장 2단계 승인**, 결재이력(개인번호/성명/일시) 저장 필수. "환원자료 전송"은 계정계/통합UI로의 결과 송신.
4. **경계 재확인**: 자출납 정산표(06-3510), "실제 시재금/회계 확인" = **계정계 소유**. ATMS는 집계·결재까지 (14번 문서 일치).

### 6000번대 → TO-BE 매핑 / 설계 시사점

| 영역 | AS-IS | TO-BE | 비고 |
|---|---|---|---|
| 장애 | 6000~6004 | 운영>용역기기/출동관리 | SLA raw, 출동차수 |

**핵심 설계 도출:**
1. **SLA 기준은 전부 마스터+이력 테이블(6208/6209/6211)**: 평가항목·배점·등급컷·용역료단가를 **하드코딩 금지**. 각 마스터에 `APPLY_MONTH`(기준월)/`수정일시` 이력 → 회의 1차#4 "항목변경=유지보수"를 코드변경 없이 처리.
2. **출동 시간추적이 SLA의 원천(6000~6002)**: 출동 1건마다 `요청→출동→도착예정→도착통보→조치완료` 타임스탬프 + 출동차수(6004) + 접수자/취소. 이걸로 6203/6204 집계 → 6208 항목 점수 → 6209 등급 → 6212 용역료.
3. **현금 대사 서브시스템(6103/6104)**: 업체신고재고 ↔ ATMS산출재고 양면대사 + 자금이체 정산. 마감(6101)/미처리(6102)/현송(6100/6105/6106)/반환(6107)이 입력. **현금정합성·횡령방지(회의 경계표)** 직결.
4. **현송 수요예측(6105)**: 전3개월평균 기반 현송계획 = 회의 경계표 "수요예측" 영역.
5. **가동률 면책(6210)**: 미가동사유로 SLA 가동률 보정 → 분쟁예방.
6. **용역료=SLA 연동(6209→6212)**: P&I적용율이 용역료 가감 → SLA가 실제 비용에 반영. 산정은 배치(atms-batch).

## 7. 시스템관리/코드/권한 7000번대 (★ 16개 전수확인 — 설계 마스터의 보고)

> ⚠️ **정정**: 7000번대는 단순 '원격제어'가 아니라 **시스템 운영의 마스터/설정 도메인**이다. 공통코드·기종모델·업체·권한·메시지 마스터가 전부 여기 있고, 이것들이 **다른 모든 도메인(1000~9000)의 코드값·기종·권한의 원천**이다. 설계 시 **가장 먼저 만들어야 할 기반 테이블**들이 7000번대에서 나온다. (16개 캡쳐 1:1 확인 완료)

### 7000 — 공지사항 (게시판)

- **조회조건**: 검색조건(전체/작성자/제목/내용) + 검색어 / 조회
- **그리드**: 순번 · 제목 · 작성자 · 작성일자 · 조회수 · 파일
- **성격**: 운영자 공지. 회의 인증연계#4 "공지 PUSH(통합UI로 밀어내기)" 연결 → 작성=ATMS, 표출=통합UI.

### 7001 — 업무연락 (게시판)

- **조회조건**: 검색조건(전체/작성자/제목/내용) + 검색어 / 조회
- **그리드**: 순번 · 제목 · 작성자 · 작성일자 · 조회 · 파일
- **성격**: 7000과 동일 구조의 **내부 업무 게시판**(첨부파일 포함). 7000/7001은 **게시판 1테이블+구분코드**로 통합 가능.

### 7002 — 명세표 에러사유 조회

- **표시**: 자동화기기 거래 명세표(거래일/취급점-기번-일련번호/매체-개설은행/계좌번호·카드번호/거래금액/원장잔액/불능코드/**에러사유**/명세표메시지1·2/에러내용/관련팀)
- **성격**: 특정 거래의 **불능(에러) 사유 + 명세표 출력 메시지** 조회. 9101 거래상세와 유사하나 **에러진단 목적**. 7203 메시지 마스터와 연결.

### 7100 / 7200 — 시스템 사용권한 부여 ★IMMS 직결

- **조회조건**: 개인사번 + (검색) / `등록`·`엑셀`·`조회`
- **탭**: 권한목록(부서별) / 권한목록(개인별)
- **그리드**: 순번 · 부서정보 · 사무소정보 · 권한 · 등록정보
- **성격**: 사용자(개인/부서)에게 ATMS 화면·기능 **권한 부여**. **회의 인증연계#1 IMMS 권한매핑**의 AS-IS 원형. TO-BE는 기존 `T_ROLE`/`T_USER`/RBAC + IMMS 매핑으로 흡수. (7100/7200은 사실상 동일 화면 — 권한관리 1개로 통합)

### 7201 — 자동화기기 코드관리 (공통코드 마스터) ★★

- **좌(코드마스터)**: 순번 · 코드구분 · 코드구분명 · 상세코드 · 상세 / `등록`·`삭제`
- **우(코드디테일)**: 순번 · 코드 · 코드명 · DATA1 · 상세 / `등록`·`삭제`
- **성격**: **코드그룹 → 코드값 2단 구조의 공통코드 관리**. ★ 세션메모리 CRITICAL GAP(T_CODE/T_CODEGROUP 마이그레이션 누락)의 정확한 AS-IS 근거. **이 화면이 곧 T_CODEGROUP+T_CODE 설계도**.

### 7202 — AriTAMS 코드관리 (ATMS 코드 카탈로그) ★★★

- 7201과 동일 구조이나 **ATMS 전용 코드구분 카탈로그**가 그대로 노출됨. 실제 코드구분 예:
  - `365BGNTI`(자동기 운영시작시) · `365CONFI`(코너 승인여부) · `365ENDTI`(운영종료시) · `365INOUT` · `365YN` · `50`(긴급공지) · `AP`/`APNAME`(ATMS AP 프로그램)/`APNO` · `APRVYN`(승인유무) · **`ATMSTAT`(자동화기기 상태)** · **`AUTHGRP`(사용권한)** · **`BASE_DA`(SLA 재산정 기준)** · **`BIZ_KIND`(마감조회 업무구분)** · `BN`(업무구분코드) · `BPSTAT`(BP 상태)/`BPTYPE`(BP 구분) · `CANCRES`(취소결과)…
  - 코드디테일 예(거리코드): 00=100m이내 / 01=1Km이내 / … / 05=점내
- **성격**: **ATMS 전 도메인의 상태/구분/기준 코드가 전부 여기서 정의**됨. 설계 시 이 카탈로그를 **공통코드 시드(seed) 데이터**로 그대로 이관해야 함. (ATMSTAT=기기상태, BASE_DA=SLA재산정기준 → 6000번대 SLA와 연결)

### 7203 — 에러메시지 관리 (메시지 마스터)

- **조회조건**: 에러메시지 구분 + 에러메시지 코드 / `등록`·`삭제`
- **그리드**: 순번 · 코드 · **명세표인자 메시지1~6** · **화면인자 메시지1~5**
- **성격**: 기기 명세표 출력문구 + 화면 표시문구를 **코드별로 관리**하는 메시지 마스터. 7002 에러사유 표시의 원천. TO-BE도 메시지 테이블화(다국어/문구변경 유지보수 대응).

### 7204 — 전문 가져오기 (전문 추적/디버깅)

- **조회조건**: 거래일자 · 사무소 · 기번 · 일련번호 · 화면번호 / 조회 → 더블클릭 시 전문내용
- **그리드**: 거래일자 · 거래시간 · 사무소 · 기번 · 일련번호 · 화면번호 · 전문길이 · 전문
- **성격**: 기기↔서버 송수신 **원시 전문(메시지) 로그 조회**. 장애분석/대사용. 저널과 별개의 **전문로그(raw packet)**. TO-BE는 if-internal/외부 전문로그 적재 후 조회.

### 7205 — 기기 원격지시(매체배포) ★사전#3 광고배포 경계

- **조회조건**: 사무소 · 기번 / 조회
- **벤더 탭**: 한컴 · FKN · 청호 · 효성 · ATEC
- **명령 버튼**: 체크대상실행 · 일반리셋 · 시범리셋 · 시범다운 · FDS폴더삭제
- **성격**: 선택 기기에 **원격 제어명령(리셋/다운/매체배포)**. '매체배포'=광고/화면 콘텐츠 배포 → 사전#3 광고배포(가져옴) 경계. **명령발행=ATMS, 콘텐츠 소스=통합UI/외부** 협의 필요.

### 7206 — 자동화기기 버전리스트

- **그리드**: 지역 · 지점명 · 점번 · 기번 · 업체명 · 기기분류 · 기종
- **성격**: 기기별 **펌웨어/SW 버전 현황**. 7205 시범다운(배포) 결과 추적과 짝. T_ATM 확장 또는 T_ATM_VERSION.

### 7207 — 실시간 거래 현황

- **거래현황 그리드**: 거래구분 × **원거래처리중(11) · 정합성조회중(21) · 정합성취소중(31) · 지방세집계중(61)**
- **타사카드망 상태**: 롯데카드현금서비스 · 롯데카드카드론 · 삼성카드 · 현대카드카드론 · 현대카드신용카드
- **성격**: 거래 **상태머신(11/21/31/61) 실시간 건수 + 외부 카드망 연결상태** 모니터. 새로고침 주기.

### 7227 — 재무회계 미완료건 모니터링

- **조회조건**: 거래일자(범위) · 새로고침
- **그리드**: 거래구분 × **거래중(STAT11) · 결과조회(STAT21) · 취소요청(STAT31) · 결과조회취소(STAT41)** · TOTAL + Legend(건수 색상 히트맵)
- **성격**: 정합성 미완료(미결제) 거래 모니터링. **계정계 정산 대사(D5)와 직결** — 7207과 같은 상태코드 체계. ATMS↔계정계 미결건 추적.

### 7208 — 자동화기기 업체/모델 코드관리 ★★ 기종 마스터

- **좌(업체코드)**: 코드값 · 업체명 — ATEC · 청호 · 효성 · FKM · 두성컴텍(공과금수납) · 내외시스템 · 한컴(공과금수납기) · 청호(공과금수납기) · 효성(공과금수납기) · NICE …
- **우(코드모델)**: 기기코드 · 기기종류 · 모델코드 · 모델이름 — CD/GCD-20000, **APTM**/GPD-20000·GPD-30000·GPD-350, **ATM**/GAT-420·GAT-500·GAT-600·GAT-1000·GAT-2000, **STM**/LC96·LC90, **외화ATM**/LC20F …
- **성격**: **업체(벤더) 마스터 + 기기종류/모델 마스터**. 7205 벤더탭·3000번대 기기관리·6000번대 SLA의 기종분류 모두 이 마스터를 참조. → T_VENDOR + T_ATM_MODEL 필수.

### 7209 — 라우터 서비스 목록 관리

- **조회조건**: COND1(화면번호) · RESULT(서비스명) · 코드명 / `등록`·`삭제`
- **성격**: **화면번호 → 서비스(전문/거래) 라우팅 매핑**. AS-IS 화면번호 체계(1000~9000)를 서비스로 연결하던 라우팅표. TO-BE는 REST 라우팅으로 대체되나, **AS-IS 화면번호↔기능 매핑 자료로 가치 큼**.

### 7210 — 자동화기기 테이블 관리 (운영자 DB 도구)

- **조회조건**: DB(ATAI/IUUS/ILAN) · SCHEMA(ATCD/ATJL/ATEZ) · TABLE 선택 / `등록`·`수정`·`삭제`
- **성격**: 운영자가 **DB 테이블 데이터를 직접 조회/수정**하는 백오피스 도구. ★ TO-BE에선 보안상 **지양/제한**(권한 강한 일부만, 감사로그). AS-IS DB 구성(ATCD=코드, ATJL=저널, ATEZ 스키마 분리)이 보임 → 마이그레이션 스키마 매핑 참고.

### 7000번대 → TO-BE 매핑 / 설계 시사점

| AS-IS | TO-BE | 비고 |
|---|---|---|
| 7000/7001 게시판 | 시스템>공지/업무연락 | 1테이블+구분코드, 통합UI PUSH |
| 7002 명세표에러 | 거래조회>명세표(에러) | 7203 메시지+거래 결합 |
| 7100/7200 권한부여 | 시스템>권한관리 | ★IMMS 매핑, 기존 RBAC 흡수 |
| 7201/7202 코드관리 | 시스템>공통코드 | ★★T_CODEGROUP/T_CODE |
| 7203 에러메시지 | 시스템>메시지관리 | 메시지 마스터 |
| 7204 전문가져오기 | 운영>전문로그 | raw 전문 적재/조회 |
| 7205 매체배포 | 운영>원격제어 | 벤더분기, 광고배포 경계 |
| 7206 버전리스트 | 운영>기기버전 | 배포결과 추적 |
| 7207/7227 실시간/미완료 | 운영>실시간모니터 | 거래상태머신, 정산대사 |
| 7208 업체/모델 | 시스템>기종마스터 | ★★T_VENDOR/T_ATM_MODEL |
| 7209 라우터서비스 | (REST 대체) | AS-IS 화면번호 매핑자료 |
| 7210 테이블관리 | (지양/제한) | 보안상 제거 또는 감사 |

**핵심 설계 도출:**
1. **공통코드 마스터가 최우선(7201/7202)**: T_CODEGROUP/T_CODE는 **모든 도메인 선행 테이블**. 7202 카탈로그(ATMSTAT/AUTHGRP/BASE_DA/BIZ_KIND/BPSTAT…)를 **시드 데이터로 그대로 이관**. (세션메모리 CRITICAL GAP 해소 근거)
2. **기종/업체 마스터(7208)**: T_VENDOR + T_ATM_MODEL → T_ATM이 이를 FK 참조. 7205 벤더분기·3000 기기관리·6000 SLA 기종 모두 의존.
3. **권한(7100/7200)=IMMS 매핑**: 회의 인증#1. 기존 RBAC(T_ROLE/T_USERGROUP)에 IMMS 권한그룹 매핑 추가.
4. **메시지 마스터(7203)**: 명세표/화면 문구를 코드화 → 문구변경=데이터(유지보수).
5. **거래 상태머신(7207/7227)**: 11/21/31/41/61 상태코드는 **거래정합성·정산대사(D5)의 핵심**. 저널/거래에 상태컬럼 + 미완료 모니터링.
6. **7210 백오피스 DB도구는 TO-BE 미이관 권장**(보안). 필요 시 강권한+감사로그 한정.

2. **거래상세 = 저널 재사용**: 신규 테이블 없이 저널(71)+원거래키(MCN_NO/DTLS_SEQNO/TARGET_TABLE)로 역추적. 1000번대 거래조회와 동일 키체계.
3. **코너 마스터 완전체(9300/9630)**: 경비업체·CCTV·인근파출소·부스·도로명 + **용역계약정보(SLA평가대상/계약기간/특별용역료)**. 3000(T_CORNER)·6000(SLA)을 잇는 **중심 마스터**. 영업점기준(9300)/용역관리점기준(9630) 두 진입점이 동일 T_CORNER 갱신.
4. **에이전트 자원정보(9322) = 신규 T_ATM_RESOURCE ★**: 에이전트가 OS/AP/Agent버전·HW스펙·IC/HW모듈·IP/MAC을 주기 보고 → 자산관리·펌웨어배포(atms-file)·호환성 점검 기반. **에이전트 설계의 핵심 산출물**.
5. **전결/승인(9303/9512)**: 긴급·광고는 요청자/승인자 분리 + 사유 + 승인상태 + 로그. 단독처리 금지(내부통제).
6. **SLA 도착시간 수기보정(9601)**: 권한·변경이력 필수(SLA점수 조작 방지) — 6000 용역료에 직결되므로 감사대상.
