# 11. 저널 수신 파이프라인 (atms-journal, 2주차)

## 개요

ATM Agent → ATMS JIF(JSON) 단방향 수신 채널.  
구 새마을금고 `atmr` 역할을 `atms-journal` 모듈이 맡는다.

```
[ATM Agent / curl]
   │  POST /api/journal/receive
   ▼
[JournalReceiveController]
   │
   ▼
[JournalDispatchService.dispatch()]   ← 절대 throw 안 함
   │
   ├─ JifFieldUtils.parseHead(msg)      → JifHeadKey
   │     └─ 실패 시 saveError(REQUIRES_NEW) → T_JOURNAL_ERROR
   │
   ▼
[@Transactional doDispatchInTx]
   │
   ├─ T_JOURNAL INSERT (IGNORE_ROW_ON_DUPKEY_INDEX → 재전송 멱등)
   │
   └─ handlerIndex.get(jnl_kind).handle()
         │
         ▼
    [AtmMonitorJournalHandler]    (jnl_kind = 21, 22)
         └─ T_ATMMONITOR INSERT (IGNORE_ROW_ON_DUPKEY_INDEX)
```

실패 처리:
- `parseHead` 실패 → `T_JOURNAL_ERROR` 기록 후 `JournalReceiveResult.accepted=false`
- 핸들러 미존재 → 정책 `journal.receive.unknown-kind-policy` (SKIP|ERROR)로 분기
- 핸들러 내부 예외 → 외부 tx 롤백 + `T_JOURNAL_ERROR` 기록 (REQUIRES_NEW)
- 중복 PK → Oracle 힌트로 silent skip

## 실행

```bash
cd Backend/nh-atms-api
./gradlew :atms-journal:bootRun
# port 8081
```

## 지원 jnl_kind 매트릭스

| jnl_kind | 의미       | 핸들러                            | 저장 테이블           | 상태 |
|---------:|-----------|-----------------------------------|----------------------|:----:|
| 21       | ATM 상태   | `AtmMonitorJournalHandler`        | T_ATMMONITOR         | ✅   |
| 22       | ATM 장애   | `AtmMonitorJournalHandler`        | T_ATMMONITOR         | ✅   |
| 52       | 운영       | `OperationJournalHandler`         | T_OPERATIONJOURNAL   | ✅ (3주차 B) |
| 71       | 거래       | `TransactionJournalHandler`       | T_TRANSACTIONJOURNAL | ✅ (3주차 A) |
| 11/12/31/41 | AP시작/서비스/마감/시재 | (전용 테이블 없음 — 본문은 T_JOURNALDATA 로 자동 보존) | T_JOURNAL + T_JOURNALDATA | ✅ (3주차 B) |

> **dispatcher 변경(3주차 B)**: 모든 jnl_kind 메시지는 dispatcher 가 T_JOURNAL 헤더 INSERT 직후 원본 JSON 을 `T_JOURNALDATA.JNL_DATA(CLOB)` 에도 자동 보존. 따라서 11/12/31/41 처럼 전용 테이블이 없는 종류도 본문 손실 없음. 향후 전용 통계 테이블이 필요해지면 해당 jnl_kind 핸들러만 추가하면 됨.

> 새 핸들러는 `JournalHandler` 인터페이스 구현 + `@Component` 만 추가하면 `JournalDispatchService.buildIndex()`가 자동 등록.

# 3주차 D — 수신 보안 (HMAC-SHA256)

`POST /api/journal/receive` 및 `/receive/batch` 호출에 대해 HMAC-SHA256 서명 검증을 추가했다. dev 기본값은 `enabled: false` 이므로 기존 로컬 흐름은 영향 없고, staging/prod 에서 환경변수로 켠다.

## 1) 서명 규약

- 알고리즘: `HMAC_SHA256(secret, timestamp + "." + rawBody)` → hex(lower)
- 헤더
  - `X-Atms-KeyId` — 키 식별자 (기본 `default`)
  - `X-Atms-Timestamp` — epoch seconds
  - `X-Atms-Signature` — hex string
- 허용 시계 오차: ±300s (`clock-skew-seconds`)
- 비교: `MessageDigest.isEqual` (constant-time)
- 검증 실패 응답:

```json
{ "success": false, "code": "AUTH_HMAC", "message": "..." }
```

## 2) 서버 설정 (atms-journal)

`application.yml`:

```yaml
journal:
  hmac:
    enabled: ${JOURNAL_HMAC_ENABLED:false}
    secret: ${JOURNAL_HMAC_SECRET:nh-atms-journal-dev-hmac-secret-change-me}
    key-id: ${JOURNAL_HMAC_KEY_ID:default}
    clock-skew-seconds: 300
```

- 필터 체인: `JournalSecurityConfig` 가 `/api/journal/**`, `/actuator/**` 만 잡고 `HmacAuthFilter` 를 `UsernamePasswordAuthenticationFilter` 앞에 둠.
- 본문 재읽기를 위해 `CachedBodyHttpServletRequest` 래퍼로 항상 감싼다 (필터에서 stream 소비 후 컨트롤러 Jackson 파싱 유지).
- 환경변수: `JOURNAL_HMAC_ENABLED`, `JOURNAL_HMAC_SECRET`, `JOURNAL_HMAC_KEY_ID`

## 3) 호출 예시 (bash + openssl)

```bash
SECRET="nh-atms-journal-dev-hmac-secret-change-me"
BODY='{"head":{"yyyy":"2025","mm":"01","dd":"15","hh":"10","mi":"00","ss":"00","fff":"000","flag":"N","atm_id":"00107404","jnl_seq":"00001","jnl_kind":"TR","jnl_enc":"N","agent_type":"NH"},"body":{"tr_cd":"WD0001","amount":"100000"}}'
TS=$(date +%s)
SIG=$(printf '%s.%s' "$TS" "$BODY" | openssl dgst -sha256 -hmac "$SECRET" -hex | awk '{print $2}')

curl -X POST http://localhost:8081/api/journal/receive \
  -H "Content-Type: application/json" \
  -H "X-Atms-KeyId: default" \
  -H "X-Atms-Timestamp: $TS" \
  -H "X-Atms-Signature: $SIG" \
  -d "$BODY"
```

`enabled:false` 일 때는 위 헤더 없이도 통과한다.

# 3주차 E — atm-simulator (JIF JSON, Virtual Thread)

`Simulator/atm-simulator` (port 9090) 가 atms-journal 로 JIF JSON 저널을 송신한다. Java 21 Virtual Thread 기반이라 5,000+ 에이전트를 가볍게 띄울 수 있다.

> 이전 개발자가 push 한 새마을금고 바이너리 송신 코드 (`JournalSender`, `JournalPacketBuilder`) 는 `@Component` 만 떼서 미사용 상태로 보존했다 — NH 실 IF 검증 단계에서 참고용으로 다시 활성화 가능.

## 1) 구성

| 컴포넌트 | 역할 |
|---|---|
| `simulator.journal.JifJsonBuilder` | head/body Map 빌드 (kind 별 분기) |
| `simulator.journal.JifJsonSender` | `targetUrl` 로 POST + HMAC 헤더 자동 부착 + Micrometer 메트릭 |
| `simulator.agent.VirtualAtmAgent` | AP_START → OPEN → 주기적 저널 송신, 실패 3회 백오프 재시도 |
| `simulator.agent.AtmAgentPool` | `count` 개 에이전트를 Virtual Thread per task 로 실행 |
| `simulator.config.SimulatorProperties` | `simulator.*` 바인딩 |

`atm_id` = `term-group-id`(5) + `term-id-prefix` + index(3, zero-pad) → 총 8자리.

## 2) 설정 (`application.yml`)

```yaml
server:
  port: 9090
simulator:
  target-url: ${SIM_TARGET_URL:http://localhost:8081/api/journal/receive}
  term-group-id: "00107"
  term-id-prefix: ""
  target-tps: 100
  journal-ratio:
    ap_start: 1
    open: 1
    status: 10
    failure: 3
    total: 1
    cash: 10
    operation: 5
    transaction: 65
  hmac:
    enabled: ${SIM_HMAC_ENABLED:false}
    secret: ${SIM_HMAC_SECRET:nh-atms-journal-dev-hmac-secret-change-me}
    key-id: ${SIM_HMAC_KEY_ID:default}
```

서버 HMAC 을 켰다면 `SIM_HMAC_*` 의 secret/keyId 가 서버와 동일해야 함.
