# 웹 화면은 어떻게 뜰까

::: lead
주소를 치고 화면이 뜨기까지 브라우저와 서버가 무엇을 주고받는지 따라갑니다. 화면을 만드는 세 가지 말과 이 책에 나오는 도구들의 이름을 익히고, 마지막에는 우리 프로젝트를 내 PC에서 직접 띄웁니다.
:::

::: goals
- 브라우저와 서버가 요청과 응답을 주고받는 모습을 설명할 수 있다
- HTML·CSS·자바스크립트와 리액트가 맡은 일을 말할 수 있다
- 우리 프로젝트에 어떤 화면이 들어 있는지 안다
- 프로젝트를 내 PC에서 띄우고 개발자 도구를 열 수 있다
:::

::: files
- `package.json`
- `vite.config.ts`
- `index.html`
:::

출근해서 업무 시스템 주소를 치고 <kbd>Enter</kbd>를 누릅니다. 1초쯤 뒤에 로그인 화면이 뜹니다. 날마다 하는 일이지만 그 1초 사이를 들여다본 적은 드뭅니다. 이 장은 그 1초를 천천히 돌려 봅니다. 화면이 어디서 오고 무엇으로 만들어지는지 알면, 앞으로 열어 볼 소스 파일이 저마다 무엇을 맡았는지 보입니다.

## 주소를 치면 일어나는 일 {#ch1-request}

은행에서 손님은 창구에 원하는 것을 말하고, 직원은 그에 맞는 것을 내줍니다. 웹도 똑같습니다. 손님 자리에 @@**브라우저**|브라우저@@(browser)가, 창구 자리에 @@**서버**|서버@@(server)가 있습니다. 브라우저는 크롬이나 엣지처럼 웹 화면을 보여 주는 프로그램이고, 서버는 보통 다른 컴퓨터에서 돌며 달라는 것을 내줍니다.

브라우저가 서버에 "이것을 주세요" 하고 보내는 것이 @@**요청**|요청@@(request), 서버가 돌려주는 것이 @@**응답**|응답@@(response)입니다. 주소창에 치는 @@**주소**|주소(URL)@@(URL)는 어느 서버의 무엇을 달라는지 적은 글입니다. <kbd>Enter</kbd>를 누르면 브라우저가 그 주소로 요청합니다. *웹은 요청 하나에 응답 하나, 이 한 쌍의 되풀이입니다.*

서버가 응답으로 내주는 것은 크게 두 가지입니다. 첫째는 **화면을 그리는 파일**입니다. 주소를 처음 치면 서버는 HTML, CSS, 자바스크립트라는 세 종류의 파일을 줍니다. 브라우저는 이 파일들을 읽어 화면을 그립니다. 우리 프로젝트에서 맨 먼저 오는 파일은 14줄짜리 `index.html`입니다. 이때의 화면은 틀만 있고 속이 비어 있습니다. 공지사항 화면이라면 조회조건과 빈 표만 보입니다.

둘째는 **화면에 채울 자료**입니다. [조회]를 누르면 브라우저가 "공지 목록을 주세요" 하고 한 번 더 요청합니다. 이번에 서버는 화면을 다시 보내지 않고 자료만 보냅니다. 아래 그림에서 ① 이 첫째, ② 가 둘째입니다. 돌아오는 응답이 서로 다른 것을 보세요.

![브라우저와 서버가 주고받는 것. 서버의 응답은 두 가지다](img/ch01-request-response.svg){width=100%}

자료는 @@**JSON**|JSON@@(제이슨)이라는 글 형식으로 옵니다. 공지 한 건이라면 이런 모습입니다.

```json title="예제 1-1 서버가 보내는 자료의 모습(JSON)"
{
  "no": 264,
  "subject": "기기 장애 통계 주간 보고",
  "visit": 14
}
```

콜론(`:`) 왼쪽이 이름, 오른쪽이 값입니다. 번호(`no`)는 264, 제목(`subject`)은 "기기 장애 통계 주간 보고", 조회수(`visit`)는 14라고 읽습니다. 브라우저는 이런 자료를 받아 표의 한 행으로 그립니다. 실제 응답은 여러 건이 한꺼번에 오고 겉에 봉투가 한 겹 더 있습니다. [[#ch12]]에서 엽니다.

브라우저에서 도는 화면 쪽을 만드는 일을 @@**프론트엔드**|프론트엔드@@(front-end)라고 합니다. 서버에서 자료를 꺼내고 저장하는 쪽을 만드는 일은 @@**백엔드**|백엔드@@(back-end)입니다. 이 책은 프론트엔드를 다룹니다.

## 화면을 만드는 세 가지 말

서버가 처음에 준 세 종류의 파일은 저마다 다른 말로 쓰여 있고 맡은 일도 다릅니다. @@**HTML**|HTML@@은 뼈대입니다. 화면에 무엇이 놓이는지 적습니다. "여기에 표, 그 위에 버튼." @@**CSS**|CSS@@는 옷입니다. 놓인 것이 어떻게 보이는지 적습니다. "버튼은 남색, 글자는 흰색." @@**자바스크립트**|자바스크립트@@(JavaScript)는 움직임입니다. 무슨 일이 생기면 무엇을 할지 적습니다. "[조회]를 누르면 목록을 받아 와 표를 채운다." HTML과 CSS는 [[#ch2]]에서, 자바스크립트는 [[#ch3]]에서 배웁니다.

자바스크립트만으로 화면을 만들면 금세 벅차집니다. 공지 한 건을 등록하면 표 맨 위에 한 줄을 끼워 넣고, "45건"을 "46건"으로 고치고, 쪽 번호도 다시 매겨야 합니다. 자료 하나가 바뀔 때마다 화면의 어디 어디를 고칠지 사람이 하나하나 적습니다. 한 군데라도 빠뜨리면 자료와 화면이 어긋납니다.

@@**리액트**|리액트@@(React)는 이 일을 대신 맡는 자바스크립트 @@**라이브러리**|라이브러리@@(library)입니다. 라이브러리는 남이 만들어 둔 코드 묶음이고, 가져다 쓰기만 하면 됩니다. 리액트를 쓰면 "자료가 이러하면 화면은 이렇다"만 적습니다. *자료가 바뀌면 화면의 어디를 고칠지는 리액트가 찾아서 고칩니다.* 리액트는 화면을 작은 부품으로 나눠 만들게도 해 줍니다. 버튼 하나, 표 하나를 부품으로 만들어 두고 여러 화면에서 다시 씁니다. 이 부품을 컴포넌트라고 부릅니다. [[#ch5]]에서 배웁니다.

리액트 혼자 일하지는 않습니다. 우리 프로젝트가 쓰는 도구를 아래 표에 모았습니다. 지금은 이름과 하는 일만 눈에 익혀 두세요.

표: 이 책에 나오는 도구. 이름 옆은 `package.json`에 적힌 이름과 버전이다

## 우리가 읽을 프로젝트 {#ch1-project}

이 책의 교재는 ATMS의 프론트엔드 소스입니다. ATMS는 은행의 자동화기기, 곧 ATM 같은 기기를 관리하는 시스템입니다. 지금 소스에 업무 화면이 다 들어 있지는 않습니다. 모든 화면이 함께 쓰는 공통 뼈대와, 새 화면을 만들 때 보고 따라 할 견본 화면이 들어 있습니다.

들어 있는 화면은 일곱 개입니다. 로그인, 홈, 견본 네 개(공통 모듈·공지사항·기기정보·기기모델코드), 그리고 장애현황입니다. 로그인하면 홈 화면이 뜹니다. 아래 첫째 그림입니다. 가운데 카드 네 장이 견본 화면 네 개로 가는 문입니다. [공지사항] 카드를 누르고 [조회]를 누르면 둘째 그림의 모습이 됩니다. 이 화면이 이 책의 목적지입니다.

둘째 그림을 보세요. 위쪽에 조회조건이 있고, [조회]를 누르면 아래 표에 목록이 뜹니다. 표의 첫 행이 [[#ch1-request]]의 예제 1-1에서 본 바로 그 자료입니다. 오른쪽 위에는 [등록], [수정], [삭제] 버튼이 있습니다. 조건을 넣고, 조회하고, 표에서 골라 고칩니다. 은행 업무 화면은 대부분 이 순서로 움직입니다. 그래서 이 화면 하나를 끝까지 만들 줄 알면 다른 화면도 같은 방식으로 만듭니다. [[#ch14]]에서 이 화면을 빈 파일부터 직접 만듭니다.

## 내 PC에서 띄우기 {#ch1-run}

화면을 직접 띄워 놓고 읽어야 책의 설명과 눈앞의 화면이 이어집니다. 준비물은 세 가지입니다.

- @@**Node.js**|Node.js@@(노드): 자바스크립트를 브라우저 밖, 곧 내 PC에서 실행해 주는 프로그램입니다. 개발 도구들이 이 위에서 돕니다. 22.13 이상이 필요합니다(`package.json` 8행).
- **VS Code**: 소스를 열어 읽고 고치는 편집기입니다.
- 브라우저: 크롬이나 엣지를 씁니다.

VS Code의 [파일] → [폴더 열기]로 `package.json`이 들어 있는 `nh-atms-web` 폴더를 엽니다. 이어서 [터미널] → [새 터미널]을 고르면 아래쪽에 @@**터미널**|터미널@@(terminal)이 열립니다. 터미널은 글자로 명령을 쳐서 컴퓨터에 일을 시키는 창입니다. 여기에 `node -v`를 치면 Node.js의 버전이 찍힙니다. 메뉴가 영어라면 [File] → [Open Folder], [Terminal] → [New Terminal]을 찾으세요.

### 설치하고 켜기

@@**npm**|npm@@은 Node.js에 딸려 오는 도구로, 라이브러리를 받아 설치해 줍니다. 아래처럼 치면 `package.json`에 적힌 라이브러리가 버전 그대로 `node_modules` 폴더에 설치됩니다. 처음 한 번만 합니다.

```bash
npm ci
```

::: tip 인터넷이 안 되는 사내망이라면
라이브러리를 새로 받아 올 수 없습니다. 팀에서 받은 npm 캐시(미리 받아 둔 라이브러리 보관함)를 PC에 넣어 두고 `npm ci --offline`이라고 칩니다.
:::

설치가 끝났으면 화면을 띄울 차례입니다.

```bash
npm run dev
```

```out
> nh-atms-web@1.0.0 dev
> vite --host

  VITE v7.3.1  ready in 115 ms

  ➜  Local:   http://localhost:3100/
```

@@**개발 서버**|개발 서버@@(dev server)가 켜졌습니다. 개발하는 동안 내 PC에서 서버 노릇을 하는 프로그램입니다. [[#ch1-request]]에서 본 "화면을 그리는 파일"을 이 서버가 내줍니다. 소스를 고쳐 저장하면 브라우저 화면도 바로 바뀝니다. 터미널을 닫으면 개발 서버도 꺼지니 열어 두세요. 끌 때는 <kbd>Ctrl</kbd>+<kbd>C</kbd>를 누릅니다.

출력의 둘째 줄 `vite --host`는 어디서 왔을까요. `package.json`에 적혀 있습니다.

```json src="package.json:10-11"
  "scripts": {
    "dev": "vite --host",
```

`npm run dev`는 `scripts`의 `dev`에 적힌 명령을 대신 실행하라는 뜻입니다.

### 주소와 포트

출력의 `Local` 줄에 적힌 `http://localhost:3100`이 우리 화면의 주소입니다. @@**localhost**|localhost@@는 내 PC 자신을 가리키는 이름입니다. 3100은 @@**포트**|포트@@(port) 번호입니다. PC 한 대에서 서버 프로그램이 여럿 돌 때 서로를 구별하는 번호로, 은행으로 치면 창구 번호입니다. 이 번호는 `vite.config.ts`에 적혀 있습니다.

```ts src="vite.config.ts:30-36" hl="2,5" marks="2=①;5=②"
    server: {
      port: 3100,
      proxy: {
        // 대상은 .env.development(.local) 의 DEV_PROXY_TARGET 으로 바꾼다
        '/api': { target: apiTarget, changeOrigin: true, configure: dropOrigin },
      },
    },
```

설정 파일의 문법은 아직 몰라도 됩니다. 두 줄만 봅니다. ① 은 개발 서버가 3100번 포트에서 요청을 받는다는 뜻입니다. ② 는 주소가 `/api`로 시작하는 요청은 개발 서버가 직접 답하지 않고 다른 서버에 넘긴다는 뜻입니다. 넘겨받는 곳은 따로 바꾸지 않았다면 `http://localhost:8080`, 곧 내 PC의 8080번 포트입니다(같은 파일 19행).

![개발할 때 내 PC에서 함께 도는 세 프로그램](img/ch01-dev-setup.svg){width=100%}

위 그림처럼 내 PC 안에서 프로그램 셋이 함께 돕니다. 브라우저가 화면 파일을 달라고 하면 개발 서버가 직접 내줍니다. 자료를 달라는 `/api` 요청은 개발 서버가 받아서 8080번 포트의 백엔드 서버에 넘기고, 응답을 받아 브라우저에 돌려줍니다. 로그인도 공지 목록도 모두 `/api` 요청입니다. 그래서 **백엔드 서버가 함께 켜져 있어야 로그인이 됩니다.** 백엔드를 띄우는 방법은 이 책의 범위 밖입니다. 팀 선배에게 물어 켜 두세요.

이제 브라우저 주소창에 `http://localhost:3100`을 칩니다. 로그인 화면이 뜨면 팀에서 받은 개인번호와 비밀번호를 넣고 [로그인]을 누릅니다. [[#ch1-project]]에서 본 홈 화면이 나오면 성공입니다. [공지사항] 카드를 누르고 [조회]까지 눌러 보세요. 조건에 맞는 공지가 없으면 표는 비어 있습니다.

::: warn 로그인 화면 대신 "사용자 정보를 확인할 수 없습니다"가 뜬다면
백엔드 서버가 꺼져 있는 것입니다. 터미널에도 `http proxy error: /api/me`라는 줄이 찍힙니다. 프론트엔드 소스가 고장 난 것이 아니니 백엔드 서버를 켠 다음 화면의 [다시 시도]를 누르세요.
:::

### 개발자 도구

브라우저에는 화면의 속을 들여다보는 @@**개발자 도구**|개발자 도구@@(DevTools)가 들어 있습니다. 화면에서 <kbd>F12</kbd>를 누르면 열립니다. 탭이 여럿인데 이 책에서는 세 개를 씁니다.

- **Elements**(요소): 화면을 이루는 HTML과 CSS를 봅니다. [[#ch2]]에서 씁니다.
- **Console**(콘솔): 자바스크립트를 한 줄씩 쳐 보고 오류 문구를 봅니다. [[#ch3]]에서 씁니다.
- **Network**(네트워크): 브라우저가 보낸 요청과 받은 응답을 봅니다. [[#ch12]]에서 씁니다.

::: try 요청과 응답을 눈으로 보기
홈 화면에서 <kbd>F12</kbd>를 누르고 Network 탭을 고른 다음 <kbd>F5</kbd>로 화면을 새로 고쳐 보세요. 줄이 수십 개 쌓입니다. 한 줄이 요청 하나와 그 응답입니다. 맨 윗줄이 HTML 파일이고, 그 아래로 `main.tsx`를 비롯한 자바스크립트 파일이 줄줄이 이어집니다. 화면 하나를 그리려고 브라우저와 서버가 이만큼 주고받습니다.
:::

이제 여러분의 PC에 우리 화면이 떠 있고, 그 속을 들여다볼 개발자 도구도 열려 있습니다. [[#ch2]]에서는 이 도구의 Elements 탭으로 화면이 무엇으로 이루어져 있는지 들여다봅니다.

::: summary
- 웹은 브라우저가 보내는 요청과 서버가 돌려주는 응답으로 움직인다.
- 서버가 주는 것은 두 가지다. 화면을 그리는 파일(HTML·CSS·자바스크립트)과 화면에 채울 자료(JSON).
- HTML은 뼈대, CSS는 옷, 자바스크립트는 움직임이다. 리액트는 자료가 바뀌면 화면을 따라 바꿔 준다.
- 우리 소스에는 로그인, 홈, 견본 화면 네 개, 장애현황이 들어 있다. 목적지는 공지사항 화면이다.
- `npm ci`로 설치하고 `npm run dev`로 켠 뒤 `http://localhost:3100`을 연다. 백엔드 서버도 켜져 있어야 한다.
:::

1. 공지사항 화면에서 [조회]를 눌렀습니다. 이때 서버가 보내는 것은 "화면을 그리는 파일"과 "화면에 채울 자료" 가운데 어느 쪽이고, 어떤 형식으로 옵니까?
2. 버튼의 색을 바꾸려면 HTML, CSS, 자바스크립트 가운데 무엇을 고칩니까? 버튼을 눌렀을 때 일어나는 일을 바꾸려면 무엇을 고칩니까?
3. `npm run dev`로 개발 서버를 켜고 주소를 열었는데 "사용자 정보를 확인할 수 없습니다"만 보입니다. 무엇이 빠졌고, 왜 그것이 필요합니까?

::: answer
1. 화면에 채울 자료, JSON 형식. 화면을 그리는 파일은 처음 주소를 칠 때 이미 받았다.
2. 색은 CSS, 눌렀을 때 일어나는 일은 자바스크립트.
3. 백엔드 서버. 로그인과 자료 조회는 `/api` 요청인데, 개발 서버는 이 요청을 8080번 포트의 백엔드 서버에 넘기기만 한다.
:::
